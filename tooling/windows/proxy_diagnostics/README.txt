蜂窝 Windows 系统代理诊断工具

适用：Windows x64 / ARM64，W-PROXY-04 (13) 等系统代理读回不一致问题。
本工具不是新客户端。不要卸载、覆盖原客户端，也不要提供账号、密码或订阅链接。

一、开始
1. 完整解压 ZIP。不要在压缩包内部直接运行。
2. 使用运行蜂窝的同一个 Windows 用户，双击 Start-Proxy-Diagnostics.cmd。
3. 通常不需要管理员权限；不要用另一位管理员账户运行。
4. 如果公司策略禁止脚本或 Add-Type，请联系公司管理员，不要关闭安全策略。
5. 启动器的 ExecutionPolicy Bypass 只用于当前检测进程，不修改电脑的执行策略。

二、首次先选 1：只读检测
保持错误发生后的状态，先检测并回传日志，不要连续点击重试。
检测读取 Unicode/ANSI WinINet 状态、当前用户/机器代理项、相关策略和已知代理进程。
会对百度和微软首页做 HTTPS HEAD 对照，不保存正文，不带账号、Cookie 或自动登录凭据。
只读模式不改系统代理、TUN、DNS、路由或客户端数据，不关闭其他软件。

三、需要时选 3：刷新修复
先从托盘完全退出蜂窝和其他代理客户端，再输入 REFRESH 确认。
工具先保存仅当前 Windows 用户可解密的本机备份，然后刷新 Windows 代理缓存/通知。
发现代理策略、读取不一致、客户端未退出或状态发生变化时，会拒绝或停止刷新。
不会重写代理地址、禁用/清空 PAC、修改组策略、执行网络重置或强制回滚别的软件的新设置。
刷新不保证修好写入兼容性、系统策略或第三方干预问题，不能以“刷新完成”作为验收通过。
因为不写代理配置，不需要用备份覆盖系统设置；如检测到外部变化，保留现场供排查。

四、选 2：连接、断开和退出验收
1. 先在蜂窝中断开连接，保持 TUN 关闭，按提示记录初始状态。
2. 点击连接。若有弹窗，保持现场，不要连续重试，回工具按回车。
3. 点击断开连接，回工具按回车。
4. 再连接一次，随后从托盘选择“退出”，回工具按回车。
工具不会代替您点击客户端，也不会强制结束进程。
通过标准包括手动代理正确接管、断开恢复初始配置、退出后客户端已退出且代理恢复。
如原来有公司 PAC，恢复初始配置不等于完全不经任何代理。
本工具不测试/修改 TUN；“不使用显式 HTTP 代理”的请求仍可能经过 TUN，不能证明已绕过 VPN。
网站返回 HTTP 状态也不能证明所有应用都走代理。请同时检查日常网站是否恢复。

五、日志回传
每次结束都会打印 FengWo-Proxy-Report-日期时间.zip 的完整位置。
默认在 %LOCALAPPDATA%\FengWoProxyDiagnostics\ 对应日期文件夹内。
请只发送这个报告 ZIP，并说明选择了哪个步骤、连接/断开/退出后实际能否上网。
代理地址、PAC 内容和排除域名在报告中仅保留随机盐哈希、长度与状态，不输出原文。
不要发送 private-backup.dpapi，也不要发送账号密码或整个客户端数据文件夹。
工具不自动上传任何日志。
