蜂窝 Windows 宽带代理只读采集

适用：W-PROXY-04 (13)，尤其客户端日志中有“宽带连接”或 RAS 的情况。
这不是修复版客户端，不安装、不覆盖原客户端，不需要账号、密码或订阅链接。

操作步骤
1. 完整解压工具包，保持蜂窝报错现场，不要连续重试，也不要删除宽带连接。
2. 使用运行蜂窝的同一个 Windows 用户，双击 Read-Ras-Proxy.cmd。
   通常不需要管理员权限，不要换另一个管理员账号代跑。
3. 等待结束，把窗口打印位置中的 FengWo-RAS-Proxy-Report-日期时间.json
   与蜂窝本次“查看/导出日志”得到的日志一起发给客服。
   默认位置：%LOCALAPPDATA%\FengWoProxyDiagnostics\ras-日期时间\。
4. 另外说明是电脑拨号还是路由器拨号，当前是否开启虚拟网卡/TUN，
   报错后是否仍能上网。不要提供宽带账号、密码或客户端账号密码。

边界和隐私
- 不写代理值，不刷新代理缓存，不修改 PAC、DNS、路由、TUN、策略，不联网探测。
- 不关闭软件，不读取网页内容，不自动上传日志。
- 仅查询当前用户默认连接及已保存连接名称对应的代理视图。
- 名称、地址、排除域名和 PAC 不以原文导出，只记录随机盐哈希、长度、数量、
  开关和差异类型。临时原文仅在当前检测进程内用于比较。
- 已保存连接不等于当前已连接；报告明确标记“活动状态未核验”。
- Unicode、ANSI、UI 和 FLAGS 查询是顺序进行的，不是原子快照。
- WinINet 查询可能触发 Windows 内部缓存同步。本工具不是用于认定“谁关闭代理”的
  被动追踪工具，不能凭前后状态变化认定写入进程。
- 对照默认连接，不代表默认连接就是客户端期望的配置。
- 排除列表的顺序、空白、大小写对照仅用于诊断，不会取消客户端的严格校验。
- 脚本不会修复这个问题，也不能验收连接、断开、退出或 TUN 清理。
- 此版已完成本机受控逻辑、解析和 C# 编译测试，尚未完成 Windows 原生执行验收。
  请先由技术人员在隔离 Windows 测试机上运行，再安排客户补充证据。
- 执行策略 Bypass 仅作用于当前 PowerShell 进程，不更改整机设置。
