# 登录凭据原生存储探针

这是独立测试应用，不是蜂窝客户端，不连接任何登录接口，不读取真实账号、订阅或 VPN 状态。

探针直接编译 `../../lib/common/local_secret_store.dart`，不维护另一套存储实现。使用独立应用标识和 `fengwo-isolated-probe.*` 键名；不调用 `deleteAll`。测试值为专用假数据。

## macOS

使用与客户端相同的 Flutter 3.44.4：

```bash
FENGWO_PROBE_FLUTTER=/绝对路径/flutter/bin/flutter ./run_macos.sh
```

脚本在探针目录生成独立 macOS 工程，编译 Release，并启动两个独立进程：

1. `seed`：写入、回读、删除会话而保留密码、重建存储实例后回读。
2. `reopen`：跨进程回读、覆盖值、不同键隔离、显式删除、删除后重新写入与清理。

`release_platform_selected` 使用与 `tooling/package_fengwo_all.sh` 一致的 `MACOS_FILE_SECRET_STORAGE=true`，应选中加密文件存储。`platform_native` 是额外的系统钥匙串检查，不代表当前 macOS 打包脚本选择的存储路径。

任一后端失败，脚本会返回非零状态，不能只看构建成功。日志在 `.results/`；结构化报告在独立测试应用的 Application Support 目录，完整位置会打印出来。报告只记录检查名称、结果、错误类型及数值系统状态，不记录密码内容。

## 其他平台

在对应系统创建探针平台工程，保持项目名 `fengwo_auth_storage_probe`、组织名 `io.fengwo.testing`，构建入口指定 `main.dart`，不要使用自动生成的 `lib/main.dart`。

Android 可通过 `--dart-define=FENGWO_AUTH_PROBE_ID=probe-自定义小写运行标识` 指定独立批次。默认 `auto` 阶段会在首次启动运行 `seed`，第二次进程启动运行 `reopen`。只允许在已明确用于本次验证的测试设备或只读模拟器中安装探针，不要覆盖生产客户端。

`build_android.sh` 只构建 Android arm64 Release 探针，不自动安装。当前环境遇到的仓库 HTTP 403 和重跑命令见 `验证记录-20260906.md`。

Windows 和 Linux 的桌面进程也可以使用 `FENGWO_AUTH_PROBE_ID`、`FENGWO_AUTH_PROBE_PHASE=seed` / `reopen` 环境变量。探针必须是独立应用，不能把它作为生产客户端的启动入口执行。

## 验收边界

这些检查证明的是实际平台存储的读写、隔离、删除与跨进程保留，不等于完整客户端“勾选记住我 → 登录 → 退出 → 登录表单回填”的界面验收，也不等于电脑重启或所有系统版本均通过。

新发布前仍须逐个平台安装候选发布包，验收完整登录与退出流程、取消记住我、账号切换、存储异常的脱敏日志和重开后回填。按本次用户最新要求，保存或退出回填失败仅写日志、不弹提示。不能用模拟存储测试或单一平台探针代替其他平台实测。
