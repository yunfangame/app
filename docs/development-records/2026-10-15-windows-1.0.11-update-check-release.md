## Repair Scope

Update checks use an independent direct HTTP transport, bounded source
deadlines and retries, and failover between the two exact trusted built-in
manifest sources. Each source must pass the existing TLS, encrypted manifest
signature and parsing checks. Redirects remain disabled. Custom update sources
do not silently fall back to production sources.

Persistent diagnostics correlate main-config loading, each source attempt,
fallback, retry and completion by check ID, without raw URLs or credentials.
Existing Bash, CMD and PowerShell environment-copy options are preserved.

Direct HTTP bypasses the application's HTTP proxy override, not the OS TUN or
DNS. On the Windows test server, both unsigned and signed TUN checks recovered
through the authenticated backup manifest after the primary source timed out.
The customer's original failure lacked incident logs; the matching connected
and TUN update-check failure was reproduced on the test server.
